# SoundFlow 0.16.6 — меньше лишней памяти и меню во время удержания

## Что сокращено в памяти
- ScApi.track больше не сохраняет полный JSON-ответ SoundCloud в каждом Track.remote: удалены длинные описания, вложенный профиль пользователя, список transcodings и прочая ненужная для списка информация. Сохранены ID, ссылка, обложка (включая fallback на аватар), доступность скачивания/потока, policy, full_duration, monetization_model, genre. Заголовок, исполнитель, длительность, лайк и причина рекомендации остаются в Track. Поток и права, как раньше, запрашиваются свежими перед воспроизведением/сохранением.
- Старые модели из локальной библиотеки/снимков тоже приводятся к компактным метаданным при чтении. Списки не обрезаются по количеству треков.
- Карточки плейлистов содержат только поля карточки, без вложенного массива всех треков и полного JSON автора.
- Снимки плейлистов перенесены из SharedPreferences (чьи строки целиком остаются в памяти процесса) в приватную SQLite-базу playlist_snapshots.db. Списки карточек читают только короткое summary; прогресс — только ID источников. Полный список читается при открытии/поиске/синхронизации, а не остаётся вложенным в каждой карточке.
- Миграция старого playlist_snapshots сохраняет все аккаунты, порядок/состав треков, requested/cached и другие поля снимка. Старые значения удаляются только после успешного завершения транзакции; уже перенесённый новый снимок старым не перезаписывается. Файлы аудио, обложки, сессия и очередь SyncDb не перемещаются. Первая миграция большой коллекции может занять время. Откат на старую версию не возвращает старый формат кэша плейлистов автоматически.
- Большой body снимка читается частями, чтобы большой плейлист не упирался в размер одной строки CursorWindow. Чтение согласовано с записью внутри процесса.
- Кэш обложек снижен с 4 до 2 MiB, ожидающая очередь — с 24 до 12 запросов; 2 worker и дедупликация остаются. Обложки на диске не удаляются. Может быть больше повторных чтений при быстрой прокрутке; размеры крупной обложки и аудиобуфер не урезаны.
- PlaybackService держит один текущий Track плюс очередь стабильных ID вместо второй полной Library на протяжении всего прослушивания. Следующий трек загружается из сохранённой библиотеки, как и раньше. При выборе трека полная библиотека ещё может временно разбираться; общий сырой кэш library в SharedPreferences этой версией не переносится.
- При закрытии большого плеера очищаются drawable и ссылки на все его View/SeekBar/текстовые поля. Раньше dismiss Dialog оставлял эти поля у Activity и мог удерживать закрытое дерево интерфейса.

Это сокращение конкретных удерживаемых данных и кэшей, а не установленный предел RAM всего приложения. Реальный PSS/RSS, исходные 500 MB и итоговое уменьшение на телефоне не измерялись. Android, WebView renderer, GPU и декодеры имеют свою память. Нельзя обещать фиксированный расход мегабайт или отсутствие пиков при загрузке большой коллекции.

## Лайки, создание и добавление в плейлисты
- Сохраняется один переиспользуемый WebView для серии операций с теми же cookies/сессией. Нет уничтожения/создания браузера после каждого лайка. Без явного намерения редактирования основной экран скрытый сайт не открывает.
- При явном открытии создания плейлиста или выбора плейлиста браузер заранее готовится параллельно вводу названия/загрузке списка. Сам прогрев ничего не записывает в аккаунт и не сообщает успех.
- После 15 секунд простоя браузер освобождается, при уходе с экрана — как раньше, если не занят. При сообщении Android о нехватке памяти освобождается только незанятый браузер; активная отправка не отменяется ради экономии RAM.
- Первый запрос после освобождения всё ещё может ждать загрузки сайта. Это компромисс памяти/скорости, а не обещание мгновенного изменения на сервере. Сетевые задержки SoundCloud не измерялись.
- Подтверждение сервера, проверка аккаунта, обработка 401/403/UNKNOWN_OUTCOME и запрет слепого повтора неизвестного результата сохранены. Успех не рисуется заранее, чужие серверы/секреты не используются.
- Аудиобуфер оставлен прежним: target6MiB, окно8–30с. Снижение RAM не достигается ухудшением устойчивости звука на слабой сети.

## Меню при удержании
- HoldListView использует один явный таймер350мс. Меню вызывается пока палец ещё на строке; после отпускания второй обработчик не открывает его заново. Native long-click/UP-путь отключён. ACTION_DOWN остаётся обработанным и тогда, когда стандартный ListView не принял его.
- Перед показом меню больше не вызывается OfflineStore.bySource со сканированием и расшифровкой всей коллекции на UI-потоке. Используется компактный индекс sourceID→localURI, уже полученный при обновлении офлайн-состояния. Фактическое удаление по-прежнему проверяется в OfflineStore.
- После срабатывания отменяется штатное касание строки и блокируется перехват родителем для этого жеста. Отпускание после удержания не запускает трек.
- Прокрутка, pull-to-refresh, CANCEL, мультитач, замена данных и отсоединение списка отменяют ожидающее удержание. Короткое обычное нажатие остаётся обычным нажатием.

## Фоновые проверки
Поведение0.16.5 сохранено: примерно15мин внутри живого процесса, без пробуждения приложения ради проверки после выгрузки; Android может задерживать таймер. Проверки без передачи файлов не создают уведомлений. Начатая очередь файлов сохраняется отдельно и может продолжаться через JobScheduler по ограничениям Android. Уведомления — только для передачи файлов и убираются после завершения.

## Сборка и проверка
assembleDebug, assembleDebugAndroidTest и testDebugUnitTest успешны. 190 Robolectric-тестов, 0 ошибок, 0 пропусков (24 новых: LeanMemory166Test17, LeanUi166Test5, WarmWriterTest+2). Android instrumentation APK только собран, НЕ запускался на устройстве.

Новые сценарии: компактность больших JSON и сохранение качества/прав/аватара; лёгкие карточки; миграция разных аккаунтов и защита нового снимка; полный список500 и body3MiB без потери; пустой известный список; requested; изоляция/очистка; отсутствие полной Library у сервиса; маленькие лимиты обложек; AlertDialog до ACTION_UP в PullRefreshLayout и в настоящем MainActivity; отсутствие повторного запуска по UP; отмена обновлением/скроллом; индекс офлайн для меню; освобождение полей закрытого плеера; прогрев только по намерению создания/добавления; CREATE/ADD на одном браузере; память освобождает idle, но не busy.

Подпись apksigner совпадает с предыдущей Flow; пакет/версия проверены aapt. Тесты синтетические: реальный телефон, PSS/RSS, реальная сеть/лайки SoundCloud, прошивка, Doze и поведение пальца на физическом экране не проверены.
