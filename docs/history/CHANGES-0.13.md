# 0.13 — inline operations, fresh playback session and original-file resume

## Account buttons
The default LIKE/UNLIKE/CREATE/ADD UI does not launch AccountWebActivity. MainActivity owns a 1x1 non-focusable, non-accessibility background WebView request transport. This is still a browser engine internally; it is not described as native HTTP or an official API integration. It loads the first-party root document, obtains current configuration, verifies /me, and executes the existing guarded script. It does not navigate the user's screen to Likes. Duplicate taps while busy are refused. Local hearts change only after server success. No automatic replay after an unknown result, and no invented successful result on403.

No hidden challenge is solved. A service-issued403 verification offers an explicit optional “Открыть проверку” action; only that action opens a visible first-party window. No automatic fallback from the initial heart button into a browser Activity. Requests cannot be guaranteed accepted by a live account/WAF merely because fixture tests pass.

## Process lifecycle
SoundFlowApplication clears only the playback checkpoint at new-process creation, and removes its stale media notification. PlaybackService is START_NOT_STICKY. Authentication, profile, library, home feed, downloads, partial permitted originals, preferences and download plans remain durable. A new process starts at Home with no old queue, seek position or automatic music resume. Ordinary screen switching in an existing process does not stop an active native service. Android force-stop cannot be intercepted or run app cleanup synchronously: the OS stops audio immediately; checkpoint cleanup happens when the app process is next created. Clear storage/uninstall is NOT used.

## Authorized original downloads
ScApi freshly checks downloadable=true before invoking OriginalTransfer. No stream/HLS route, DRM removal, recording, entitlement change, foreign key, backend or permission bypass was added. An original-file response can be resumed with Range and If-Range only after a strong ETag or valid Last-Modified, known full size and matching current track metadata. Metadata contains identity/version/size/validator, not signed URLs or tokens. A new authorized endpoint is resolved on each save attempt. Credentials still go only to API hosts, never the audio CDN.

Validated partial bytes survive network errors, cooperative cancellation and process death in private app storage. Progress includes existing bytes. Content-Range start/end/total and response size are checked; partial data is never marked playable. A changed entity or200 response restarts by truncation, never concatenation.416 triggers one fresh restart. Weak/missing validators cannot safely resume; incomplete files restart in that case. Permission/auth failures do not bypass the provider. Explicit sign-out/clear-offline removes partial originals. Protected HLS remains governed by a real offline licence; interrupted protected downloads are NOT claimed to have byte-resume in this release.

## Autoload
The running automatic task checks the saved plan flag and a per-plan revision at cancellation boundaries, without the former one-second cached flag. Off then on cannot revive the old task. Disabling invalidates its running task and cancels periodic/one-shot/retry scheduling when no enabled plans remain; it never deletes ready tracks. Cancellation remains cooperative: a blocking network read can take its normal timeout, but its result is checked before further writes/commit.

Retryable item failures remain durable with backoff. Enabled plans get a network-constrained one-shot retry job503;429 Retry-After and the Wi-Fi setting are preserved. Periodic background execution is still subject to Android scheduling, not an exact timer. Explicit manual downloads remain manual and are not cancelled by turning off a separate autoload plan. “Продолжить / повторить ошибки” uses the saved list and existing bytes instead of first requiring another playlist fetch; ready tracks are skipped. “Повторить отдельный трек” selects one failed source and reuses its account-scoped partial original. A confirmed saved source updates counters across playlists without altering their order or deleting other items. Cancelling returns the interrupted queue item to pending, not a false successful/ready state.

## Remaining unavailable track
NO_OFFLINE_SOURCE for2413615341 is not claimed fixed. The earlier anonymous probe found downloadable=false and a full clear online stream, not persistent-download permission. Its metadata is in offline-public-metadata.json and is explicitly a historical public-network result, not a new authenticated check. No recording or restricted stream copying is implemented. Local audio import already exists in the app for files obtained legitimately.
