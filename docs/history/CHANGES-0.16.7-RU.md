# SoundFlow 0.16.7 — постоянный плеер и лайк в уведомлении

## Плеер больше не выгружается через30секунд
- Удалены idleRelease/stopIdle и таймер принудительного завершения после паузы. Обычная пауза сохраняет реальный плеер, буфер, очередь и MediaSession; это не замена плеера одной карточкой продолжения.
- На паузе foreground-служба воспроизведения и её уведомление остаются. Пауза отпускает аудиофокус; Media3 не должен держать playback wake-lock как при воспроизведении. Удаление карточки приложения из недавних само по себе больше не останавливает плеер.
- Системная команда MediaSession Stop/команда STOP останавливает музыку как пауза, не удаляя выбранный трек, очередь и карточку. Для настоящего удаления предусмотрена отдельная явно названная кнопка «Убрать плеер»; logout/удаление текущего файла тоже по-прежнему могут остановить плеер полностью. DISMISS оставлен как явная команда закрытия для внутренних тестов/совместимости.
- Периодический секундный учёт прослушивания и запись checkpoint каждые5с не продолжаются бесконечно на обычной паузе; они запускаются вновь при загрузке/воспроизведении. Состояние на паузе сохраняется один раз.
- При обычном onDestroy службы очередь остаётся в checkpoint и, если плеер не был явно закрыт, публикуется обычная карточка «На паузе» с продолжением/лайком/закрытием. Это резерв после реального уничтожения службы, а не30-секундная штатная стратегия. Пока служба жива, действует настоящий MediaStyle/MediaSession.
- Старт/продолжение из карточки использует PendingIntent.getForegroundService, а явное закрытие — отдельный receiver, не запускающий пустую службу.

## Интерфейс остаётся до необходимости освободить память
- При простом сворачивании сохраняются дерево интерфейса и его уже загруженные изображения/кэш; ненужные запросы обложек приостанавливаются, UI-тикер не работает. Большой плеер также не закрывается автоматически из-за одного onStop.
- TRIM_MEMORY_UI_HIDDEN сам по себе не считается нехваткой памяти. При реальном RUNNING_LOW/CRITICAL, BACKGROUND и более высоких уровнях очищается кэш и освобождается незанятый браузер записи.
- Скрытый незанятый MainActivity может освободить дерево View, картинки, списки моделей и свою Library. Активная запись в аккаунт/загрузка экрана не прерывается вслепую ради этого. При следующем открытии восстанавливается навигационный контекст/поисковая строка, список строится заново; позиция прокрутки вне сохранённой домашней подборки может сброситься. Плеер этой операцией не останавливается.
- Обработан и onLowMemory. Когда интерфейс видим, дерево не удаляется из-под пальца — освобождаются только кэши/незанятый транспорт.

ВАЖНО: Activity и PlaybackService всё ещё в одном Linux-процессе. Это разделение ресурсов и жизненного цикла, НЕ отдельный процесс плеера. Android не гарантирует callback перед уничтожением процесса и может завершить его целиком; принудительная остановка, ограничения прошивки и выключение телефона не обходятся. Для независимого убийства UI-процесса и сохранения аудиопроцесса нужна отдельная IPC-архитектура — в0.16.7 она не реализована. Служба START_STICKY/checkpoint помогают восстановлению по разрешению Android, но не гарантируют непрерывный звук после убийства всего процесса. Сохранять реальный плеер на паузе может требовать больше RAM, чем прежний принудительный30-секундный stop: это осознанный компромисс по запросу пользователя.

## Лайк из уведомления
- Добавлена кнопка сердца с текущим состоянием: «В любимое»/«Убрать лайк». В MediaStyle она доступна в развёрнутой карточке; для Android13+ опубликованы custom-action и heart-rating в MediaSession. Конкретное расположение/число видимых кнопок определяет Android/прошивка; три компактные кнопки остаются Назад/Пауза/Далее. Для обычного локального файла без SoundCloud ID сердце не предлагается.
- Действие привязано к ID трека, владельцу аккаунта и желаемому состоянию в момент построения уведомления. При переключении на следующий трек старый tap не лайкает новый. В отличие от слепого toggle это явные LIKE/UNLIKE.
- Основной экран не открывается ради записи. Используется тот же first-party AccountWriter, теперь поддерживающий application Context и WebView без Activity. Сессия, проверка /me, реальное подтверждение, обработка403/401/UNKNOWN_OUTCOME и запрет невидимого прохождения проверки сохраняются.
- Для длительности отправки запускается отдельная ограниченная foreground-служба с временным уведомлением «Отправляем изменение…» (ID9, не музыкальный ID7). На Android34+ это shortService, на более старых версиях — совместимый dataSync. Writer имеет прежний deadline60с, после завершения браузер/служба закрываются.
- Сердце не меняется до успеха SoundCloud. После успеха обновляются локальная библиотека, офлайн-метаданные, текущая медиасессия/карточка и видимый список. При отказе показывается обычное сообщение о неподтверждённой записи; основная карточка музыки не удаляется. При неизвестном результате автоматического повторения нет, чтобы не дублировать изменение.
- Одновременные операции AccountWriter из основного экрана и уведомления сериализованы общим gate. При занятом транспорте новый запрос не выдаётся за отправленный/успешный. Двойной tap в занятой службе не посылает второй запрос.
- Явно закрытая карточка не появляется вновь из-за запоздалого подтверждения лайка; результат по треку при этом сохраняется. Смена аккаунта до результата не применяет лайк к новому аккаунту.

## Остальные условия и проверки
Автопроверка плейлистов остаётся примерно раз в15мин только в живом процессе, без отдельного запуска процесса ради проверки. На паузе плеер теперь сохраняет процесс foreground, поэтому таймер может продолжать работать, если он ранее запускался открытием интерфейса. Запуск только службы уведомления сам по себе таймер не создаёт. Передача файлов остаётся отдельной очередью.

Также устранено узкое окно повторного запроса обложки: кэш повторно проверяется под lock после завершения другого worker. Асинхронный тест обложек теперь ждёт фактического присвоения drawable, а не только окончания загрузки.
