# SoundFlow 0.16.8 — локальное аудио «Своё»

## Вкладка и выбор файлов
- Навигация: Для вас → Поиск → Своё → Медиатека.
- «Добавить аудио» открывает системный ACTION_OPEN_DOCUMENT для audio/*; можно выбрать несколько файлов. Запрошен LOCAL_ONLY, чтобы системный проводник предлагал локальные источники.
- Сохраняются только content:// ссылка с постоянным read-доступом, название/исполнитель/длительность, дата добавления и позиция. Аудиофайл не копируется в каталог приложения, не загружается на сервер и не помещается в офлайн-кэш SoundCloud. Поддержка постоянного SAF-доступа обязательна; если провайдер её не выдаёт, импорт отклоняется вместо обещания недолговечной ссылки.
- Внутренний ID local:UUID отделяет пользовательское аудио от SoundCloud и его офлайн-записей. Реальный content:// разрешается только перед воспроизведением. Никакой подмены файла облачным треком нет.
- Повторное добавление той же URI обновляет метаданные, не создаёт дубликат и сохраняет дату добавления/позицию. Два разных URI с одинаковым названием — разные записи. После удаления записи повторное добавление начинает новую историю.
- Сортировки: сначала новые, сначала старые, по названию. Новизна определяется датой добавления в приложение, не датой создания/изменения исходного файла. Выбор сохраняется; названия сравниваются с русской локалью без учёта регистра.
- Вкладка работает без входа в SoundCloud. Для этих файлов нет лайка SoundCloud и облачных действий. Есть обновление свайпом и меню удержания по существующему таймеру350мс до отпускания пальца.

## Позиции и воспроизведение
- У каждого файла собственная позиция в SQLite. При выборе/возвращении к файлу воспроизведение начинается с неё. Уход на другой трек не перезаписывает позицию другого файла.
- Позиция фиксируется при паузе, переключении, перемотке, закрытии плеера и обычном уничтожении службы, а во время активного воспроизведения — примерно раз в5с. При аварийном убийстве процесса последние секунды могут потеряться: Android не гарантирует callback.
- После полного окончания позиция данного файла сбрасывается в0. Повтор трека/списка использует существующий механизм; «Своё» считается списком.
- Для воспроизведения content:// применяется существующий Media3-плеер и DefaultDataSource. Поддержка конкретного кодека определяется Media3/Android. Встроенные обложки не извлекаются/не декодируются в коллекцию; используется лёгкая заглушка, без добавления крупного bitmap-кэша.
- Сохраняется поведение0.16.7: нет30-секундного принудительного завершения плеера на паузе; уведомление и очередь остаются. Скрытый интерфейс освобождается при давлении памяти, а не при обычном сворачивании. Архитектура остаётся однопроцессной; уничтожение процесса Android может прервать звук.

## Удаление и недоступность
- Удержать файл → «Убрать только из приложения» либо «Удалить вместе с файлом». Оба действия требуют отдельного подтверждения. Первое не вызывает удаление у провайдера, убирает ссылку/позицию/сохранённый доступ. Второе просит документ-провайдер удалить исходный файл, затем убирает запись.
- Если источник сейчас играет, плеер останавливается перед операцией. Отказ удаления сохраняет запись и её позицию, но не обязан автоматически возобновлять остановленный звук.
- Удаление исходника возможно только если провайдер/Android разрешает его. RecoverableSecurityException Android29+ открывает системное подтверждение и повторяет операцию только после согласия. При прочем отказе предлагается убрать запись только из приложения. Приложение не получает общий доступ ко всему хранилищу и не обходит запрет удаления.
- При подтверждённом исчезновении файла запись удаляется вместе с bookmark и ссылкой в глобальном checkpoint очереди. Поздняя запись позиции выполняет UPDATE, не INSERT, и не воскрешает удалённый элемент. Удаление распространяется в открытый список через внутреннее событие.
- Проверка ссылок выполняется при открытии/возвращении во вкладку, обновлении свайпом, перед воспроизведением и при ошибке чтения. Постоянного фонового сканера/пробуждения процесса для локальной коллекции нет. Поэтому внешнее удаление отражается при следующей такой проверке, а не гарантированно мгновенно.
- Отозванное разрешение, неизвестная ошибка/недоступность провайдера и отключённый externalstorage-том не считаются удалением; ссылка и позиция остаются. Для externalstorage проверяется mounted-состояние тома; для стороннего провайдера один FileNotFoundException без надёжного локального подтверждения не приводит к очистке. Поведение необычных провайдеров следует проверить на устройстве.
- Ссылки и позиции «Своё» отдельны от аккаунта SoundCloud и его офлайн-кэша. Выход из SoundCloud их не очищает; удаление приложения/очистка данных удаляет эту базу, а не сами исходные файлы.

## Проверки и ограничения
Все указанные автоматические тесты — синтетические Robolectric/API-сценарии, в основном SDK28, а не прослушивание на телефоне. Новые проверки охватывают ссылки/гранты/дубликаты/сортировку, независимые позиции, отсутствие копирования в filesDir, удаление и отказы, безопасное распознавание недоступности, навигацию/SAF/множественный импорт, меню/подтверждение, контекст повторов и передачу content:// с bookmark в фабрику плеера. В локальных player-тестах prepare подменён, декодирование реального файла не выполняется.
Instrumentation APK собран, но не запущен. Физический телефон, реальные SAF-провайдеры/SD/кодеки, воспроизведение/удаление Android29+/35 и восстановление после реального LMK не проверены. Расход RAM не измерялся и конкретный лимит MB не обещается. Прежние SoundCloud-тесты сохранены.
