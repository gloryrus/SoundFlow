# SoundFlow 0.16.4 — память, жесты и управление

## Обновление
Установить поверх Flow 0.16.0–0.16.3, без удаления приложения/очистки данных. Пакет com.farika.soundflow; versionCode 17. Сертификат совпадает с предыдущими Flow: e5f7a6fe6edb98459740e2283e205405e067edddb6268147614cc25c3f10bb6f. Старую Offline Test 0.15.1 этот APK не обновляет. Скачать заново офлайн-музыку для обновления не требуется.

## Память: устранённые лишние расходы
- Убрана автоматическая загрузка скрытой полной страницы SoundCloud на каждом onStart. Обычное прослушивание и открытие медиатеки больше не создают AccountWriter/WebView заранее.
- Браузер записи создаётся только при явном лайке/изменении плейлиста. Серия действий может переиспользовать страницу, но через 15 секунд простоя WebView уничтожается. При уходе с экрана незанятый браузер закрывается сразу; выполняющаяся операция не отменяется вслепую.
- В невидимом транспорте заблокирована загрузка картинок сайта; JavaScript, cookies, проверка origin и подтверждение реального результата сохранены. Это не относится к видимой странице входа. При простое renderer получает низкий приоритет, при отправке — BOUND. Потеря renderer обрабатывается без падения хоста; неизвестный результат не выдаётся за успех и не переотправляется автоматически.
- Список использует RowHolder/convertView: строки, TextView, ImageView и фон переиспользуются, а не создаются заново при каждом обновлении/прокрутке. Состояние сердца, заголовка, причины рекомендации и обложки обновляется при привязке новой строки.
- Subtitle офлайн-прогресса плейлиста сохраняется в лёгком кэше строк, а не разбирает полный JSON списка при каждом getView; кэш сбрасывается при обновлении сохранённых ID/экрана.
- Новая ArtworkLoader: кэш не более 4 MiB вместо прежних 12 MiB; максимум 2 worker и 24 ожидающих запроса; запросы одного URL/размера объединяются; ссылки на ImageView слабые, устаревшая привязка не обновляется.
- Миниатюры запрашиваются и декодируются под размер строки (до 192 px), отдельная крупная обложка — до 768 px. CDN-вариант для миниатюры t200x200 вместо t500x500; чтение с диска также с inSampleSize и RGB_565. Устаревшие/лишние задачи сбрасываются, результаты после скрытия UI не наполняют кэш заново.
- При onStop очищаются кэш и drawable интерфейса, при возврате изображения восстанавливаются. Memory trim очищает кэш, а при скрытом UI — и drawables. Это не уничтожает скачанные аудиофайлы и обложки на диске.
- Явный LoadControl Media3: target allocator 6 MiB, временное окно 8–30 секунд, начало 1.5 с, после rebuffer 3 с, backbuffer 0. Системный декодер, аудиотрек, сеть и прочие структуры имеют свою память: 6 MiB — не ограничение всего процесса.

Эти изменения ограничивают конкретные источники лишнего расхода. Профиль реального телефона, исходные 500 MB и фактическое уменьшение PSS/RSS не измерялись. Нельзя утверждать, что приложение теперь всегда занимает фиксированное число мегабайт. WebView renderer, GPU/декодеры, размер коллекции и политика Android влияют на показатели.

Возможный компромисс: первый лайк после длительного простоя может ждать создания страницы. Короткая серия лайков переиспользует транспорт; достоверность подтверждения сервера не пожертвована ради скорости.

## Повтор
- Для всех очередей из медиатеки (Любимое, открытый плейлист, Офлайн, результаты поиска по плейлистам) последовательность: выключен → один трек → весь текущий список → выключен.
- Контекст передаётся в PlaybackService и сохраняется в checkpoint. В «Моей волне»/рекомендациях и общем поиске: выключен → один трек → выключен.
- Повтор списка относится к переданной очереди (например, отфильтрованным результатам поиска), не изменяет плейлист на сервере.

## Мини-плеер / загрузки
- Перед кнопкой play/pause добавлена стрелка «Предыдущий трек»; следующая стрелка сохранена. Управление умеет восстановить сервис из checkpoint, если плеер был освобождён после паузы.
- Кнопка загрузок остаётся одной в шапке медиатеки. Во время фактической работы DownloadSync стрелка пульсирует и рисуется движущаяся дуга. Запланированный auto-check, Wi-Fi wait и простое наличие авто-плана не считаются активным скачиванием.
- Счётчик работы account-scoped, сбрасывается в finally и охватывает foreground/job-путь. Анимация останавливается после работы, при скрытии/отсоединении View. При системном/пользовательском отключении анимаций остаётся статическое обозначение активности.

## Свайп вниз
- Убрана кнопка перезагрузки подборки «Для вас». Pull-to-refresh добавлен для «Для вас», Любимого, коллекций плейлистов, каждого открытого плейлиста и Офлайна.
- Обновление запускается только при жесте вниз у верхнего края списка и при отсутствии уже выполняющегося запроса. Обычная прокрутка, горизонтальный жест, слишком короткое движение, CANCEL/мультитач не запускают обновление. Поля ввода и ползунки не перехватываются.
- Показан небольшой встроенный индикатор, убираемый при успехе/ошибке. В Офлайне обновляется локальная коллекция, сеть не требуется. Текущая музыка не перезапускается от обновления списка.

## Подсказки и удержание
- Все вызовы Toast.makeText приложения удалены. Краткие сообщения отображаются в обычной строке состояния/встроенном TextView, без всплывающих подсказок. Tooltip-текст View очищается, accessibility content descriptions сохранены.
- Подтверждения удаления/выхода, сообщения о неподтверждённой записи и проверки сервиса не отключены: это функциональные диалоги, не подсказки. Системные окна/уведомления Android и содержимое официального сайта не подавляются.
- HoldListView открывает меню через 350 мс, пока палец ещё на строке. Отпускание после открытия не запускает трек и не вызывает меню второй раз. Движение выше touch-slop, смена указателей, CANCEL, pull-to-refresh и уход с экрана отменяют таймер. Перед открытием проверяется, что строка всё ещё представляет тот же объект.
