# Волна • Вход — 0.2.1-loginfix

Экспериментальная диагностика подключения обычного аккаунта SoundCloud.

## Установка

Это отдельное приложение с идентификатором `com.farika.soundflow.loginfix`.
Оно устанавливается рядом с прежней «Волна Direct». Удалять прежнюю версию
не нужно. Её данные и авторизация не переносятся. Новый APK подписан другим
тестовым ключом и не является обновлением поверх прежней установки.

1. Установите APK «Волна • Вход».
2. Откройте вход и авторизуйтесь на официальной странице в окне приложения.
3. Нажмите «Готово». При необходимости откроется библиотека сайта.
4. Только после успешного ответа `/me` SoundCloud покажется подтверждение
   имени аккаунта. Нажмите «Подключить».
5. Если подключения нет, выберите «Диагностика» → «Скопировать».
   Отчёт не содержит паролей, cookie, значений токенов или полного URL.

Вход в отдельном Chrome не переносит сессию в приложение. Полноценный вход
через внешний браузер требует отдельной зарегистрированной OAuth-интеграции;
эта тестовая версия её не заменяет. Пароль вводится только на странице
SoundCloud; приложение не читает поля пароля и не внедряет JS/JS-мост.

## Изменения

- Проверка cookie `oauth_token` на текущей официальной странице и дополнительных
  доменах SoundCloud вместо одного ограниченного списка адресов.
- Наблюдение заголовка Authorization в запросах своего WebView/Service Worker
  исключительно к HTTPS api-v2.soundcloud.com и api.soundcloud.com.
  Сами запросы сайта не подменяются. Никакие cookies из других приложений
  не извлекаются.
- Поддержка OAuth и Bearer, сопоставление публичного client_id сайта.
- Подтверждение подлинной сессии напрямую через SoundCloud `/me`, затем
  отдельное согласие на подключение показанного аккаунта.
- Сохранение сессии в зашифрованном виде с AndroidKeyStore.
- Различимые ошибки HTTP, TLS, DNS, тайм-аута и диагностика без секретов.
- Сохранена защита от скриншотов в окне входа.

Это не официальный OAuth SDK и не одобренное SoundCloud приложение.
Веб-интерфейс SoundCloud может изменяться, а подключение может быть недоступно.
Гарантировать успешную авторизацию нельзя. Снятие региональных, платных
или лицензионных ограничений, скачивание запрещённых автором потоков и
удаление рекламы сервиса не реализованы. Приложение не добавляет своей рекламы.

## Тесты

Парсер AuthCapture покрыт автономными JVM-тестами, не отправляющими токены
в сеть. Для запуска (JDK 21):

```sh
mkdir -p build/tests
javac -d build/tests app/src/main/java/app/volna/direct/AuthCapture.java tests/AuthCaptureTest.java
java -cp build/tests AuthCaptureTest
```

Реальный вход в личный аккаунт разработчиком не проверен: тестового аккаунта
и согласия на использование чужих учётных данных нет. Проверка личного входа
остаётся на устройстве владельца аккаунта. Не присылайте пароль или токены.

## Проверка этой сборки

- Release APK успешно собран; подпись APK v2 и zipalign проверены.
- Все 23 автономных теста AuthCapture прошли.
- На эмуляторе Android API 26 проверены установка, запуск нативного экрана
  и диалог диагностики. В образе не настроен рабочий провайдер WebView,
  поэтому загрузка сайта и распознавание реальной веб-сессии здесь не проверены.
  Добавлена понятная ошибка вместо падения при отсутствии WebView.
- Визуально проверены экран отсутствующего WebView и диалог диагностики
  на размере 432×936. Полный экран сайта не проверен.
- Тестовый инструмент не включён в распространяемый APK; он снимал защиту
  скриншота только с гостевого окна эмулятора для проверки макета.
  В распространяемом приложении FLAG_SECURE сохранён.

## Сборка

JDK 21, Android platform 35, build tools 35.0.0, Gradle 8.9.
`build-apk.sh` создаёт локальный тестовый ключ и собирает release APK.
Ключи, персональные настройки SDK и сборочные каталоги не включены в архив.
Следующая самостоятельная сборка без того же ключа не обновит установленную.
