# Проверки 0.4.0-mixes

Дата сборки/тестов: 2026-10-23. JDK21, Gradle8.9, AGP8.7.3, SDK35, Media3 1.5.1. AOSP Android8.0/API26, 432×936.

## Сборка / обновление

- Release APK собран, vital lint и проверка дублирующихся классов прошли.
- Сертификат тот же, что у 0.3.0 и 0.2.1-loginfix: `56126d63328d881b2da3d228f83d7065f174d5648ec1acd122173fc99c0e0036` (SHA256).
- `adb install -r` обновляет тот же applicationId без удаления приложения. versionCode 5.

## JVM: 54 проверки

- AuthCapture: 23 проверки нормализации авторизации/доменов, синтетические строки.
- StreamPolicy: 20 проверок MIME/протоколов/ранжирования/валидации.
- RecommendationRanker: 11 проверок уникальности, пустого набора/лимита, различий знакомого и нового, мягкого разнообразия исполнителей и штрафов.

Все JVM-тесты без сети и реальных токенов. Это проверка правил ранжирования, **не исследование качества рекомендаций для живых пользователей**.

## Android: 13 базовых + 20 изолированных сценарных проверок

### NativeSmoke — 13

Версия 0.4.0, шифрование/отказ при изменении ciphertext, допустимые домены, недопустимый офлайн-путь, отсутствие Widevine с понятным отказом, запрет загрузки без сессии, чтение синтетической офлайн-записи, проигрывание синтетического WAV, пауза/перемотка, фон и удаление.

Публичный resolver Hootie Frutti дополнительно вернул метаданные полного Widevine HLS. Это **не проверка лицензии или защищённого воспроизведения**. Токены/подписанные URL в отчёт не выводились.

### ScenarioSmoke — 20 (на окончательном APK)

Весь HTTPS в этом test-процессе заменён синтетическими ответами до установки синтетической авторизации; неизвестные HTTPS-адреса блокируются. Никакого реального аккаунта и реальных операций на SoundCloud нет.

- POST `/likes/tracks/create` и `/delete`, OAuth-заголовок, JSON `likes[].target_urn`, отсутствие query client_id/client_secret.
- Ответ 403 остаётся отказом: без анонимного ретрая/ложного успеха. Реальный интерфейс релизного APK показывает диалог с `LIKE_MOBILE_403`.
- Долгое прослушивание и быстрый пропуск по-разному влияют на локальный вкус; скрытые треки учитываются.
- Пакетная загрузка синтетического плейлиста: два разрешённых оригинала сохранены, одно превью не сохранено. Состав из трёх позиций и порядок остаются в снимке; результат `2 / 3` честный.
- Второй плейлист с теми же двумя треками не скачивает и не хранит их второй раз.
- Исходный `sc:<id>` воспроизводится через локальную копию, не нужно заходить в общий «Офлайн».
- Превью определяется как превью, персональная смесь объединяет несколько источников и исключает скрытые/preview-позиции, нет повторяющихся ID.
- Подтверждение загрузки целого плейлиста видно в реальном интерфейсе.

Сценарные загрузки использовали только синтетический WAV и разрешённые оригиналы. **Реальную выдачу offline-лицензии SoundCloud этот тест не имитирует как доказанный результат.**

## Визуальная проверка

Просмотрены снимки новых экранов на 432×936: волна с режимами и объяснениями, плейлист с `2 / 3` и отметками ↓/превью, играющая сохранённая копия и нативный плеер, полный диалог отказа лайка, подтверждение пакетной загрузки. Данные на сценарных снимках синтетические; в релизном APK демо-аккаунта и демо-каталога нет.

## Реальная проверка публичного Hurt

Официальная публичная страница `https://soundcloud.com/christianreindl-music/hurt-feat-lloren` вернула `SNIP`, `SUB_HIGH_TIER`, duration30000, full_duration216085 и только snipped=true 30-секундные варианты. Это ограничение публичного контекста доступа, не отсутствие поддерживаемого кодека.

**Проверка с авторизованным аккаунтом пользователя не выполнялась.** Нельзя объявлять полную версию Hurt разблокированной или гарантировать, что любой обычный аккаунт может её получить.

## Не подтверждено в этой среде

- Успешная запись лайка/снятие лайка на настоящем аккаунте через новый mobile endpoint. Mock-проверка формата и 403 не заменяет это. Если реальный сервер продолжает отказывать, нужны точный код и проверка сессии; это не маскируется локальным сердечком.
- Синхронизация настоящих приватных плейлистов, их изменения и полномочия конкретной сессии; соответствующий read/write API может измениться.
- Widevine/provisioning, реальные streaming/offline-лицензии и защищённая музыка в авиарежиме на физических устройствах. В тестовом AOSP Widevine отсутствует. Код соответствующего пути сохранён из 0.3.0.
- Субъективное качество «выше Spotify/Яндекс/SoundCloud». Реализована более многосоставная эвристика; сравнение на живых вкусах не проводилось.
- Все регионы/тарифы/устройства, отсутствие рекламы сервиса, живые/master-only HLS, отзыв лицензии, длительные фоновые очереди и потеря питания.

## Короткая проверка пользователем

1. Установить поверх 0.3.0. Не удалять старую версию.
2. Поставить один лайк и сверить его в своём SoundCloud. Если снова отказ — прислать `LIKE_MOBILE_403`/точный код, без паролей/cookies/токенов. Выход из аккаунта удаляет новые офлайн-копии: не выполняйте его не читая подтверждение.
3. Открыть небольшой плейлист → ↓ → дождаться итогового `N / M`. Отключить сеть, открыть тот же плейлист и проиграть треки с отметкой ↓. Общие копии должны также быть в «Офлайн».
4. Переключить Микс/Открытия/Знакомое; слушать и пропускать треки. Локальная история постепенно влияет на следующие обновления волны.
5. Проверить Hurt: если SoundCloud выдаёт только превью, приложение должно явно это показать, не выдавать 30 секунд за полный скачанный трек.
