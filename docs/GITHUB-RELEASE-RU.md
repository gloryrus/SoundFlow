# Автоматическая публикация SoundFlow

Этот workflow заменяет `.github/workflows/build-apk.yml`. Код приложения не меняется. Исправление SDK включено: setup-android устанавливает platform-tools, не удалённый пакет tools. Сборка работает на Ubuntu24.04 с Java21/SDK35.

## Обычный выпуск

1. В `app/build.gradle` задайте новую `versionName` (например1.0.1) и увеличьте `versionCode` (например24 вместо23).
2. Сделайте commit и push в main.
3. GitHub сам соберёт и проверит подписанный release APK, создаст тег v1.0.1 на том же commit и опубликует Release с SoundFlow-1.0.1.apk и SHA256. Ручные git tag и отдельный запуск на теге не нужны.

Изменения только Markdown/лицензий не запускают сборку. Запуск вручную: Actions → SoundFlow Auto Release → Run workflow → main. Это также публикует Release, если версия ещё свободна. Старые теги не являются триггером и workflow их не передвигает.

## Подпись

Используются уже настроенные Repository secrets: SOUNDFLOW_KEYSTORE_BASE64, SOUNDFLOW_STORE_PASSWORD, SOUNDFLOW_KEY_ALIAS, SOUNDFLOW_KEY_PASSWORD. Ключ не создаётся заново. Не удаляйте ключ или Secrets при уборке истории. Успешные предыдущие сборки уже показали, что ваша подпись работает.

## Уже занятая версия

Если v1.0.0 указывает на старый commit, workflow специально остановит публикацию с понятной ошибкой, а не подменит исходники/выпуск. Если версия уже распространялась, выпустите1.0.1 с большим versionCode. Для ещё не опубликованного стартового тега возможна осознанная ручная очистка после резервного копирования истории; она не выполняется этим workflow.

Повтор того же commit не перезаписывает опубликованные assets. Новые выпуски требуют новой versionName, а совместимые Android-обновления — большего versionCode и той же подписи/пакета. Не меняйте release-ключ между сборками.

## Ограничения

Нужны разрешённые Actions и возможность job publish получить contents:write; правила организации могут ограничивать эти разрешения. Публикация использует штатный github.token, отдельный PAT не нужен.

CI проверен локально по YAML/shell/Python и моделям публикации; в вашем GitHub с вашими Secrets ещё не запускался. Эта настройка не стирает старые коммиты/теги и не меняет приложение автоматически. Переписывание Git-истории — отдельная операция и не требуется для работы автопубликации.
